# 시크릿 관리 계획 (dotenvx)

2026-11-16 작성. 상태: **6단계(배포)까지 완료** (11/18)

## 문제

- `server/.env` 는 git 제외 파일이라 PC 를 바꿀 때마다 키를 콘솔에서 하나씩 다시 찾아 넣어야 한다.
- 11/16 새 PC 에서 `.env.example` 만 있어 `DATABASE_URL` 을 Neon 콘솔에서 다시 가져왔고, Firebase·카카오·AED·게이트웨이 키는 아직 비어 있다.
- 관리 대상: `DATABASE_URL`, `TEST_DATABASE_URL`, `GATEWAY_KEY`, `GATEWAY_PHONE`, `AED_API_KEY`, `KAKAO_JS_KEY`, `FIREBASE_SERVICE_ACCOUNT`

## 비교한 방법

| | 암호화 `.env` 커밋 (dotenvx) | 시크릿 관리 서비스 (Doppler, Infisical) |
| --- | --- | --- |
| 새 PC 준비 | 개인 키 1개를 `.env.keys` 에 넣으면 끝 | CLI 설치 + 로그인 + 프로젝트 연결 |
| 추가 의존성 | npm 패키지 1개 (`@dotenvx/dotenvx`) | 외부 계정, PC 마다 CLI 설치 |
| 시크릿 위치 | 리포 안 (암호문) | 외부 서비스 |
| 변경 이력 | git 커밋으로 남음 | 서비스 대시보드 |
| 팀 공유·권한 분리 | 개인 키를 공유하는 방식이라 약함 | 사용자별 권한, 감사 로그 |
| 비용 | 없음 | 무료 플랜 한도 있음 |
| 기존 코드 변경 | `import 'dotenv/config'` 2곳 교체 | 실행 명령을 `doppler run -- …` 로 감쌈 |

## 결정: dotenvx

- 개발자 1명, 키 7개 규모라 외부 서비스의 권한·감사 기능이 필요 없다. 계정·CLI 를 늘리는 비용이 더 크다.
- 들고 다닐 것이 **개인 키 1개**로 줄어든다. 이 키만 비밀번호 관리자에 둔다.
- dotenv 제작자가 만든 후속 패키지라 `dotenv/config` 를 그대로 대체할 수 있고, 값을 읽는 `src/config.ts` 로직은 바뀌지 않는다.
- 키가 바뀌면 커밋으로 남아 다른 PC 에서 `git pull` 만 하면 된다.
- 팀원이 늘거나 권한 분리가 필요해지면 그때 시크릿 관리 서비스로 옮긴다 (암호화된 `.env` 를 복호화해 그대로 가져갈 수 있음).

## 주의할 점

- **개인 키(`DOTENV_PRIVATE_KEY`)가 새면 리포의 모든 시크릿이 열린다.** `.env.keys` 는 반드시 git 제외, 개인 키는 비밀번호 관리자에만 둔다.
- 리포 공개 여부를 확인할 것. 암호문이라 공개 리포에서도 원칙상 안전하지만, 개인 키가 한 번이라도 새면 과거 커밋까지 모두 복호화된다. 그때는 키 교체뿐 아니라 **각 서비스의 실제 키를 재발급**해야 한다.
- 키 이름(`DATABASE_URL` 등)과 공개 키는 평문으로 보인다. 값만 암호화된다.
- 암호화된 `.env` 를 수동으로 편집하지 말고 `dotenvx set` 으로 바꾼다 (평문으로 덮어쓰면 그 값이 평문으로 커밋된다).

## 진행 계획

1. **준비 (키가 모두 있는 다른 PC)** — `git pull` → `npm install` 후 `server/.env` 에 빠진 키가 없는지 확인한다. 비어 있으면 아래처럼 채운다.
   - `FIREBASE_SERVICE_ACCOUNT`: Firebase 콘솔에서 서비스 계정 키 재발급 → 한 줄 JSON (이전 키는 콘솔에서 삭제)
   - `KAKAO_JS_KEY`, `AED_API_KEY`: 각 콘솔에서 조회
   - `GATEWAY_KEY`: 이전 값을 모르면 새로 생성 → 게이트웨이 앱 설정도 같이 바꿈
   - `GATEWAY_PHONE`, `TEST_DATABASE_URL`: 필요할 때 채움
2. **패키지 교체** — 완료 (11/16, `@dotenvx/dotenvx` 2.38.2). 평문 `.env` 도 그대로 읽으므로 암호화 전에도 동작한다. typecheck·build·테스트 31개 통과, `/healthz` `db: ok` 확인
   - `npm install @dotenvx/dotenvx`, `npm uninstall dotenv`
   - `src/config.ts`, `test/api.integration.test.ts` 의 `import 'dotenv/config'` → `import '@dotenvx/dotenvx/config'`
3. **암호화**
   - `npx dotenvx encrypt` → `server/.env` 값이 암호문으로 바뀌고 `server/.env.keys` 에 개인 키 생성
   - `.gitignore` 에서 `.env` 를 빼고 `.env.keys` 추가. `server/.env` 커밋 전 `git diff` 로 평문 값이 없는지 확인
   - 개인 키를 비밀번호 관리자에 저장
4. **확인**
   - `npm run build`, `npm run typecheck`, `npm test`
   - 서버 실행 후 `/healthz` 가 `db: ok`
   - `.env.keys` 를 잠시 다른 이름으로 바꾸면 복호화가 실패하는지 확인
5. **문서**
   - README 의 서버 실행 절차를 "`server/.env.keys` 에 개인 키 넣기 → `npm install` → `npm run dev`" 로 수정
   - `.env.example` 은 키 목록·설명용으로 유지
6. **배포 (Render, WBS 1.9 때)**
   - 운영 값은 `server/.env.production` 으로 따로 암호화 (`npx dotenvx encrypt -f .env.production`)
   - Render 환경변수에는 `DOTENV_PRIVATE_KEY_PRODUCTION` 하나만 등록. dotenvx 가 `.env.production` 을 읽도록 `DOTENV_ENV`(또는 시작 명령의 `-f`) 설정 방식은 그때 확인

## 새 PC 에서 할 일 (적용 후)

1. 비밀번호 관리자에서 개인 키를 꺼내 `server/.env.keys` 에 `DOTENV_PRIVATE_KEY=...` 로 저장
2. `npm install` → `npm run dev`

## 기타

- `.env` 의 `DATABASE_URL` 은 개발 진행 기록대로 `sslmode=verify-full` 로 둔다 (11/16 새 PC 에서 `require` 로 넣었다가 수정).
- 앱(`app/`)·게이트웨이(`gateway/`)는 시크릿 파일이 없다. 앱 Firebase 설정(`lib/firebase_options.dart`)은 공개용 값이고, `local.properties` 는 SDK 경로뿐이다.
