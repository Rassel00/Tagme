# 응급안심 WBS · 작업 우선순위

기준 문서: 「응급안심 개발 문서」(2026-11-09)
작성일: 2026-11-16

> **가정**: 시연까지 약 5주(W1~W5), 담당 역할은 BE(백엔드)·WEB(웹)·APP(Flutter)·GW(게이트웨이)로 나눔. 공수는 1인 기준 일(MD)이며 대략값이다. 팀 인원·마감일이 확정되면 일정 칸만 조정한다.

## 1. 우선순위 배정 원칙

문서의 P0/P1/P2(기능 중요도)에 **"시연 흐름이 끊기는가"**와 **"늦게 발견하면 되돌리기 어려운가"**를 더해 작업 순서(★ 순위)를 정했다.

| 작업 순위 | 의미 | 포함 |
|---|---|---|
| **★1 리스크 선제 확인** | 막히면 설계를 바꿔야 하는 것. 첫 주에 끝낸다 | iOS 개발자 계정, 게이트웨이 SMS 발송·수신 실험, Flutter NFC 쓰기 실험, AED API 키 신청 |
| **★2 핵심 경로(P0)** | 시연 시나리오 9.1의 ①~⑧을 끝까지 잇는 최소 기능 | BE-01~07, WEB-01~04, GRD-01~03, GW-01~04, APP-01·02·04~07 |
| **★3 시연 완성도(P1)** | 없어도 시연은 되지만 설명력이 떨어지는 것 | WEB-05·06, GRD-04, GW-05, BE-08·09, APP-03·08·09 |
| **★4 여유 시(P2)** | 시간이 남을 때만 | APP-10~13 |

### 순서를 이렇게 잡은 이유

1. **백엔드 → 웹을 앱보다 먼저**: 신고·승인·문자 흐름이 서비스의 핵심인데 전부 백엔드와 웹에 있다. 태그·연락처는 시드 스크립트로 넣으면 앱 없이도 ③~⑧을 먼저 검증할 수 있다.
2. **게이트웨이는 W1에 실험부터**: 사업자 없이 문자를 보내는 유일한 수단이라 실패하면 대안(예: 보호자 화면만으로 시연)을 일찍 정해야 한다. 장문 분할 발송과 요금제 한도도 이때 확인한다.
3. **앱은 병렬로 진행**: 앱 팀은 W1~W2에 로그인·NFC를 백엔드 없이 만들고, W3에 API를 붙인다.
4. **P1 중 AED(WEB-06)와 본인 확인(GW-05·BE-09)은 P1 안에서 가장 먼저**: 발표에서 기능 차별점으로 보여주기 좋고, 데이터 적재·문자 수신은 실기기 테스트가 필요해 시간이 든다.

## 5. 착수 전에 정할 것

문서의 미결 사항과, 문서를 읽으며 확인이 필요해 보인 부분이다.

| 항목 | 제안 | 비고 |
|---|---|---|
| 연락처 최대 인원·공개 시간 기본값·신고 만료 | 3명 / 30분 / 24시간 그대로 확정 | 문서 10장 미결 |
| 이름 기본 공개 여부 | 기본 비공개, 공개 화면은 "등록 사용자" | 문서 10장 미결 |
